# 第五天報告：用真實資料驗證準確度

日期：2026-11-19
結論：**用 735 個真實突變驗證後，修正了一個 bug，並重新校正證據強度。** 校正後，「strong」只在 2,401 筆輸入中的 2 筆指錯位置。驗證過程中還發現一個 AFDB 落後 UniProt 的真實案例。

---

## 一、驗證方法

- **資料：** 用固定亂數種子，從 UniProt 抽 200 個已審核的人類蛋白質：150 個有訊號胜肽，50 個只有起始甲硫胺酸被移除，並取它們的天然變異（每個蛋白質最多 10 個）。
- **標準答案：** UniProt 天然變異的位置是依標準序列標註的，所以可以當作正確答案。
- **做法：** 把突變改寫成文獻常見的錯誤編號，丟給工具，看它找不找得回正確位置，以及有沒有把巧合當成強證據。
- **重現方式：**

```bash
python3 benchmark/run_benchmark.py --cache 快取資料夾
```

抽樣結果存在 `benchmark/dataset.tsv`，完整結果在 `benchmark/results.md`。

| 情境 | 做法 | 期望結果 |
|---|---|---|
| A | 照 UniProt 正確編號輸入 | 全部對得上 |
| B | 扣掉訊號胜肽或起始甲硫胺酸，每個突變單獨輸入 | 找回正確位置 |
| C | 同 B，但整批輸入 | 找回正確位置，巧合對上的要被標示 |
| D | 整批位移一個沒有標註依據的隨機量（5～60） | 整批時找到共同位移；單獨時不該給強證據 |
| E | 位置隨機打錯 1～3 格 | 不該給強證據 |

## 二、第一輪結果暴露的問題

### 問題 1：真實資料不一致——AFDB 落後 UniProt

照正確編號輸入時，有一個蛋白質的突變幾乎全部對不上：**生物素酶 BTD（P43251）**。

- UniProt 在 **2026-01-28** 更新了標準序列（改用另一個異構體，從 543 個胺基酸變成 523 個，起點往後移 20 個）
- AFDB 的模型仍是 2009 年的舊序列，而且 AFDB API 中的「UniProt 序列」欄位也是舊的
- 結果：**用現行 UniProt 編號看 AFDB 模型，全部差 20 格**
- 工具原本的版本檢查只比對 AFDB 自己的兩個欄位，所以沒抓到；但工具靠「共同位移」自動找出了 +20

**這也暴露一個 bug：** UniProt 的加工標註（例如訊號胜肽）是依現行序列標註的位置，工具卻直接套用到舊序列的模型上，位置會錯。

**修正：** 工具現在會直接比對 AFDB 模型序列和現行 UniProt 序列。
- 如果其中一條是另一條的一段，就算出位移量，把 UniProt 標註換算到模型位置上，並把這個位移列為一種有依據的解釋
- 如果無法對應，就不使用 UniProt 標註，並發出警告

### 問題 2：「strong」太寬鬆

第一輪中，只有一個突變時，「剛好符合 UniProt 標註的位移」都被標成 strong。但數據顯示：
- 對照組（隨機打錯 1～3 格）有 9.3% 被給了 strong。打錯 −1 格和「沒算起始甲硫胺酸」根本無法分辨。
- 整批輸入時，「能說明 2 個以上突變」這條門檻在大批輸入（例如 10 個突變）時太寬鬆，光靠巧合就有約 8% 的機率達到。

**修正：**
- **單一突變**符合標註位移 → **medium**（不是 strong）
- **多個突變**符合同一個標註位移 → 用二項分布計算「光靠巧合能說明這麼多個突變」的機率，並依候選位移的數量做 Bonferroni 校正，小於 0.05 才算 **strong**

## 三、修正後的結果（193 個蛋白質、735 個突變）

BTD 從 B～E 情境中排除，因為它的 UniProt 位置不等於模型位置，不能當標準答案；它另外列在報告中。

| 情境 | 正確位置是第一個建議 | 指向錯誤位置的 strong |
|---|---|---|
| A. 正確編號 | 735/735 對得上 | – |
| B. 傳統編號，單一突變 | 92.4%（標示為 medium） | 0% |
| C. 傳統編號，整批 | 99.4%（其中 92% 為 strong） | 0% |
| D. 無標註位移，整批（≥3 個） | 81.6% | 0.3%（2 筆） |
| D. 無標註位移，單一突變 | 原理上無法得知 | 0% |
| E. 打錯 1～3 格 | 原理上無法得知 | 0% |

### 怎麼解讀

- **strong 幾乎可以直接相信**：2,401 筆輸入中只有 2 筆指錯。
- **medium 大約 9 成正確**：剩下的 1 成是單一突變無法分辨的巧合。
- **單一突變有 7～9% 會「碰巧對上」**，完全無法偵測。整批輸入時，大部分會被標示 `!?`，漏網的降到 1% 以下。這是工具最重要的使用建議：**要把整份清單一起檢查。**
- **無標註位移的整批情境只找回約 8 成**：只有 3 個突變時，在一條長蛋白質上，隨機符合的機會不夠低，工具選擇保守、不回報。這是刻意的取捨。
