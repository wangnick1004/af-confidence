## 二、三個新發現（會修正先前的說法）

### 發現 1：AFDB 現在**有收錄異構體**了 ⚠️ 修正先前說法

我先前說「AFDB 只收標準異構體」，**這是錯的（或已過時）**。API 對 P04637 回傳了 9 筆模型：標準的 `P04637` 加上 `P04637-2` 到 `P04637-9`。

**對專案的影響：** 這反而是加分點。當突變對不上標準序列時，工具可以自動檢查「是不是對得上某個異構體」，並提示使用者：「你可能用的是異構體 X 的編號。」

### 發現 2：AFDB 現在也有**複合體預測** ⚠️ 修正先前說法

網站程式碼中有 multimer、ipTM、ipSAE 等複合體評分。所以「AFDB 只有單體」這句話不完全正確。TP53 標準模型這筆是單體（`isComplex: false`），但影片中講限制時，要改說「**這個**模型是單體預測」，不能說「AFDB 只有單體」。這點我還沒深入查證，第二天會確認。

### 發現 3：下載檔案必須帶 User-Agent

API 查詢正常，但下載模型檔案時，如果請求沒有帶 User-Agent，伺服器會回傳 403 拒絕。程式中要固定加上 User-Agent。這是一個實作細節，已記下。

### 其他觀察

- 模型版本已是 **v6**（建立日期 2025-08-01）。程式不能把版本號寫死，要從 API 讀檔案網址。
- API 回傳的序列、PDB 檔內的序列、UniProt 的序列三者一致。
- 每個蛋白質還附有 **AlphaMissense** 預測檔（`aa-substitutions.csv`）。我們的工具**不使用**它，以免越界到致病性判斷，所以也沒有放進 repo。
