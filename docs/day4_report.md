## 一、新增功能

| 功能 | 用法 | 說明 |
|---|---|---|
| 輸入基因名稱 | `af-confidence HBB E6V` | 透過 UniProt 查詢，只採用已審核（reviewed）的條目；別名也查得到（p53 → TP53） |
| 其他物種 | `af-confidence Trp53 R172H --organism 10090` | 預設為人類（9606），小鼠是 10090 |
| 輸入異構體編號 | `af-confidence P04637-2 R175H` | 以該異構體的模型為比對對象 |
| 一份清單混合多個蛋白質 | `af-confidence -f 清單.txt` | 每行開頭寫蛋白質，後面接突變；`#` 之後是註解 |
| 同一蛋白質自動合併 | — | 清單中用基因名稱和 UniProt 編號寫的同一個蛋白質會合併檢查，批次證據才完整 |
| 單一蛋白質出錯不影響其他 | — | 例如 titin 在 AFDB 沒有模型，只回報它的錯誤，其他照常輸出 |

範例清單：`examples/mixed_proteins.txt`

```
HBB      E6V            # sickle cell, legacy numbering
SERPINA1 E342K, E264V   # Z and S alleles
P04637   R175H R72P
TTN      R100W          # titin: no AlphaFold DB model
```

## 二、穩定性處理

| 情況 | 處理方式 |
|---|---|
| 網路暫時失敗（連線中斷、逾時、HTTP 429/5xx） | 最多重試 3 次，等待時間逐次加倍 |
| 查無資料（HTTP 404） | 不重試，直接回報清楚的錯誤訊息 |
| 快取檔損壞 | 連網時自動重新下載；離線時回報是哪個檔案壞了 |
| 寫入快取到一半中斷 | 先寫到暫存檔再改名，不會留下寫一半的檔案 |
| UniProt 標註抓不到 | **明確警告**「位移解釋未檢查」，不再靜默略過 |
| AFDB 模型用的是舊版 UniProt 序列 | 警告，並以模型序列為準 |
| 基因名稱對應到多個蛋白質 | 列出所有候選，請使用者改用 UniProt 編號 |

## 三、設計上的取捨

### 長得像突變的基因名稱

`C1S`、`F2R`、`C4A` 都是真實的基因名稱，但寫法和突變一樣（例如 C1S 也能讀成「第 1 個 C 變成 S」）。規則：
- 命令列的第一個詞**一律**當作蛋白質
- 清單檔中，一行有兩個以上的詞、而且命令列沒有指定蛋白質時，第一個詞當作蛋白質
- 命令列有指定蛋白質時，清單中像突變的詞就當作突變

不確定時，用 UniProt 編號最保險。README 已寫明。

### 異構體的加工標註

UniProt 只在標準條目上標註加工區段（訊號胜肽等）。輸入異構體編號時，**只有在異構體的 N 端序列和標準序列完全相同**的情況下，才沿用 N 端的標註。例如 P01009-2 前 355 個胺基酸和標準序列相同，所以沿用「訊號胜肽 1–24」。
